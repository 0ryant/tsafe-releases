# Full comparison: tsafe 4.1.0 → 4.2.0

This comparison describes the final published 4.2.0 source and distribution
surface. It is based on frozen source `53663a4a02e943bba6aee73f99541dd1fc77593b`
and the ADO 1078 artifacts.

## User-visible differences

| Area | 4.1.0 | 4.2.0 |
| --- | --- | --- |
| Secret delivery | Authorized child receives secrets through its environment | Optional `--secret-stdin[=KEY]` delivers selected values on stdin without environment injection |
| Stdin timeout | No secret-stdin delivery path | Large input to a non-reading child is supervised and exits 124 on timeout |
| Environment selection | `--only` wording could confuse parent inheritance with secret selection | `--only` and `--keys` diagnostics clearly distinguish parent variables from vault keys |
| MCP | rmcp 3.1.2 and 2025-11-25 initialization | rmcp 3.3.0, 2026-07-28 discovery, private zero-TTL catalog, legacy initialization compatibility |
| Bound MCP authority | Existing plan/run/status boundary | Same three-tool boundary, packaged modern/legacy lifecycle proof, raw-secret refusal retained |
| Windows paths | Canonical path spellings could reject an allowlisted target | Absolute and `\\?\` spellings compare correctly without widening basename or workdir checks |
| TUI themes | Dark, Light, High Contrast | Ten presets, F2 editor, semantic overrides, dedicated `theme.json`, legacy read-only fallback |
| Fedora source build | CLI keyring graph required `dbus-devel` | CLI, agent, and MCP use pure-Rust Secret Service; tray/meta dependencies remain explicit |
| Linux distribution | Existing 4.1.0 APT channel | Signed 4.2.0 DEB/RPM channels for x86_64 and aarch64 with verified metadata |
| Installation ownership | Cargo owns its install prefix | RPM owns `/usr/bin`; DNF does not remove or upgrade a Cargo copy |

Secret-stdin removes environment injection for tools that read stdin. It does
not prevent a child from printing or otherwise leaking the plaintext it receives,
and the planned no-secret-in-child egress proxy is not part of 4.2.0.

## Crates and binary bundle

The 15 published crates are:

- 4.2.0: `tsafe`, `tsafe-cli`, `tsafe-core`, `tsafe-attest`,
  `tsafe-mobile-core`, `tsafe-tui`, `tsafe-nativehost`, `tsafe-agent`, and
  `tsafe-mcp`.
- 1.2.3: `tsafe-aws`, `tsafe-azure`, `tsafe-gcp`, and `tsafe-tray`.
- 1.2.2: `tsafe-bitwarden` and `tsafe-collab`.

`tsafe-mobile-ffi` remains `publish = false`. `tsafe-core` is required in the
dependency closure and was published before its crates.io consumers; Fedora
receives that code compiled into the executables, not as a separate RPM.

The signed default-core-full OS bundle contains `tsafe`, `tsafe-ui`,
`tsafe-agent`, and `tsafe-mcp`. The Cargo meta-crate additionally installs
`tsafe-nativehost` and `tsafe-tray`.

## Release and security changes

- Rust minimum and pinned toolchain moved to 1.98 / 1.98.1.
- Release packaging uses locked dependency graphs, deterministic embedded
  timestamps, exact asset allowlists, and separate workspace/meta-crate audits.
- RPM signing verifies package identity, dependencies, full payload metadata,
  detached repository metadata signatures, and tamper rejection.
- APT construction covers amd64 and arm64 and preserves the existing 4.1.0
  trust key for upgrade continuity.
- Windows MCP packaged parity, generated diagnostic allowlisting, UTF-8 secret
  scanning, WSL worktree handling, serialized environment-sensitive tests, and
  release-helper regressions were corrected.
- Release publication is separate from preparation, signing credentials are
  step-local, and incomplete signing fails closed.

## Branch and work decisions

The RC considered the custom themes work (`74b589cd`), Fedora support work,
MCP lifecycle work, password-order and unattended-unlock work, release-plz
changes, typed test work, and the provider/package branches. Functional changes
were included when patch-equivalent or merged into the frozen candidate;
stale generated outputs, unfinished mobile/browser/cloud work, major dependency
upgrades without proof, and unrelated branch-only governance artifacts were
deferred.

## Evidence and limits

- ADO pipeline 25 / run 1078 passed Windows x64, Linux x64, and ARM64.
- Public Fedora x86_64 DNF and Ubuntu amd64 APT consumers passed signed install,
  package verification, version, and binary-hash checks.
- ARM64 signed payloads pass direct QEMU smoke tests; native ARM64 Fedora
  installroot scriptlets were not promoted as a native-host proof.
- No Authenticode, Apple notarization, or cosign claim is made.
